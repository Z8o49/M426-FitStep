# Definition of Done und Abnahme · Sprint 2

Diese Liste bei der tatsächlichen Prüfung ausfüllen. Sie enthält die weiterhin geltenden Kernfunktionen und die Ergänzungen dieses Stands.

## Definition of Done

- [ ] Die vereinbarten Story-Gruppen sind anhand der Prüfungen erfüllt.
- [ ] `npm run verify` läuft erfolgreich.
- [ ] Neue Daten bleiben nach vollständigem Schliessen und Öffnen erhalten.
- [ ] Live- und Demo-Schrittverläufe bleiben getrennt.
- [ ] Bedienung und Eingabefehler wurden auf dem Zielgerät geprüft.
- [ ] Review-Ergebnis und offene Punkte sind nachvollziehbar dokumentiert.

## Manuelle Abnahme

| Bereich | Prüfung |
|---|---|
| Navigation | Alle Tabs bedienen; kleine Bildschirmbreite, sichere Bereiche und geöffnete Tastatur prüfen. |
| Schritte und Woche | Im Demomodus +100 / +1'000 verwenden. Heute, Dashboard und Wochenwert aktualisieren sich. Genau sieben Kalendertage anzeigen. |
| Tagesziel | Gültigen Wert speichern; leere Eingabe, 0, negative Werte und Dezimalzahlen abweisen. |
| Fortschritt | Unter, genau auf und über das Ziel gehen. Prozentwert, Restschritte und Ring prüfen. |
| Distanz · neu | Im Demomodus 1'000 Schritte ergänzen: Die Schätzung steigt um 0,75 km. Die Anzeige bleibt als geschätzt gekennzeichnet. |
| Eigene Ziele · neu | Ziel hinzufügen, abhaken, erneut öffnen und löschen. Andere Ziele bleiben unverändert. Leere beziehungsweise zu lange Texte abweisen. |
| Name · neu | Namen ändern und speichern. Anzeige und gespeicherter Name stimmen überein. Leeren beziehungsweise zu langen Namen abweisen. |
| Speicherung | Profil, Tagesziel, eigene Ziele samt Haken, Modus und Schritte ändern; App vollständig schliessen und wieder öffnen. Werte bleiben erhalten. |
| Datentrennung | Demo-Schritte ergänzen und zu Live wechseln. Live enthält keine Demo-Schritte. |
| Sensor | Echtes Gerät: Berechtigung erlauben und gehen. Auch verweigerte Berechtigung beziehungsweise fehlenden Sensor und die angebotenen Aktionen prüfen. |
| Tageswechsel | Bei einem tatsächlichen lokalen Tageswechsel neue Zuordnung und erhaltenen Verlauf prüfen. |

## Tatsächliches Ergebnis festhalten

Notiere Gerät beziehungsweise Browser, ausgeführte Handlung, erwartetes und beobachtetes Ergebnis sowie offene Fehler. Die automatisierte Prüfung und die manuellen Ergebnisse werden getrennt dokumentiert.

Für Review und Retro: Welche Stories lassen sich vorführen? Wo bestehen bekannte Grenzen? Was hat im Team geholfen? Welche konkrete Verbesserung nehmt ihr in Sprint 3 mit? Die Antworten stammen aus eurer eigenen Durchführung.
